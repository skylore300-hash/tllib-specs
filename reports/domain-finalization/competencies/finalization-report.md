## Sources inspected

All source IRs retain their raw status `canonical_declarative_ir_with_reservations`. This raw historical status was not converted into scientific executability or production readiness.

## Common patterns

The 13 source IRs demonstrate a common structural descriptor pattern:

- exact public feature identity;
- an ordered source-object profile;
- opaque scientific payloads;
- complete source provenance;
- immutable descriptor construction;
- exact-set, uniqueness and provenance validation;
- propagation of reservations and unresolved;
- rejection of unsupported scoring, thresholds, simulation, ranking, comparison and scientific evaluation;
- deterministic construction for identical structural inputs.

These patterns establish a common representation schema and reusable implementation subgraphs. They do not establish scientific equivalence between features or objects.

## Optimizations and normalization

The finalized package applies only demonstrated, semantics-preserving optimizations:

- one common descriptor schema;
- one common structural validation pipeline;
- one structured error model;
- one unsupported-scientific-operation guard;
- profile-driven preservation of source object order;
- normalized traceability from contract to source IR to finalized IR to algorithm to oracle;
- explicit separation of scientific/documentary dependencies from runtime dependencies;
- explicit preservation of same-name but distinct objects in feature 008;
- explicit preservation of unresolved relation endpoints in feature 016.

No scientific equation, metric, constraint, operator or relation was simplified or evaluated. No source IR or contract was replaced.

## Finalized IRs

Each of the 13 features has a finalized IR under `registry/optimized-ir/competencies/<FEATURE_ID>/ir.yaml` with status `selected_for_competencies_implementation_specification`.

That status selects the IR as the software work specification for the Competencies module only. It does not make a new scientific decision.

Every finalized IR includes:

- source contract and source IR references;
- raw source IR status;
- declarative nature;
- competency reference and exact identities;
- scope and opaque source context;
- inputs, outputs, types and opaque values;
- preconditions, application conditions and explicit prerequisites;
- manifestations and relations without invented execution semantics;
- operations, order and control flow;
- explicit treatment of mobilization, exercise, acquisition, development, mastery, evaluation and comparison;
- effects, postconditions, invariants, errors and determinism;
- dependency, unresolved and reservation propagation;
- applied structural transformations and preservation obligations;
- algorithm and oracle links;
- actual structural and scientific implementation readiness;
- mandatory preservation and non-invention attestations.

## Algorithms

Each feature has a directly implementable language-neutral algorithm under `registry/algorithms/competencies/<FEATURE_ID>/algorithm.yaml`.

The algorithms implement only observable behavior authorized by the selected contracts:

1. validate structural request mode;
2. validate exact feature identity;
3. validate the exact source object set, uniqueness and absence of additions;
4. validate provenance completeness;
5. read the feature profile;
6. copy opaque payload identities in source order;
7. attach traceability, raw status, dependencies, reservations and unresolved;
8. mark the descriptor structurally valid;
9. return an immutable descriptor.

Requests for unsupported scientific execution are rejected before descriptor construction. No algorithm evaluates an equation, computes a metric, selects a threshold, creates a level, simulates evolution, infers a relation endpoint or performs a competency comparison.

## Oracles and acceptance tests

Each feature has an oracle under `registry/oracles/competencies/<FEATURE_ID>/oracle.yaml`.

The oracles cover, as relevant:

- nominal structural construction;
- feature and object identity;
- types, exact shapes and source order;
- preconditions and errors;
- provenance and reference conservation;
- opaque-value propagation;
- scope and context conservation;
- manifestation and relation non-invention;
- deterministic and metamorphic order behavior;
- dependency propagation;
- rejection of unsupported acquisition, development, mastery, evaluation, comparison and scientific execution;
- full traceability consistency.

No oracle creates a competency, measurement, level, threshold, progression, comparator, observer result or relation endpoint. Numerical scientific tests remain explicitly blocked because the selected contracts do not define executable semantics.

## Module specification

`registry/domain-finalization/competencies/module-specification.yaml` defines the complete structural Competencies module:

- 13 public feature operations;
- shared internal validation and descriptor operations;
- immutable public types and structured errors;
- identity, scope, context and dependency rules;
- clear separation between representation, validation, reference, contextual association, relation, mobilization, exercise, manifestation, acquisition, development, mastery, comparison and evaluation;
- composition, ordering and determinism rules;
- external observer, comparator and evaluator requirements for unsupported requests;
- library interfaces for a future structural C++ implementation and Python bindings without generating either in this phase;
- explicit out-of-scope scientific behavior.

## Decisions and blockers

There is no blocker for implementing the structural descriptor module specified by this package.

Real blockers remain for scientific execution:

- all 13 features lack a selected validated executable scientific contract for their equations, metrics, constraints, operators or relations;
- types, dimensions, units, domains, initial conditions, thresholds, observer/evaluator rules and temporal semantics remain incomplete where calculation would require them;
- features 004 and 006 retain an external unreconciled Capacities dependency.

These blockers are preserved and classified rather than converted into implementation assumptions. Other questions are preserved as opaque values, external references, external observer/comparator/evaluator requirements or implementation-out-of-scope items.

## Future implementation tasks

`registry/domain-finalization/competencies/implementation-tasks.yaml` defines shared module tasks and one feature packet per active feature. Future developers can implement immutable types, the profile registry, structural validation, descriptor construction, error guards and the oracle harness without revisiting the source scientific content.
