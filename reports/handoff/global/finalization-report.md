# Feature Handoff Package v1.0 — global finalization report

## Scope

The Feature Handoff Package v1.0 model is the language-neutral programmer-facing projection of the complete `tllib-specs` production corpus.

The finalized projection contains:

- 36 complete domain catalogs;
- 694 autonomous feature packages;
- 8 versioned shared contracts;
- one deterministic global catalog;
- one official handoff validation CLI;
- deterministic standalone export validation for every feature;
- global audit evidence and implementer documentation.

## Population integrity

The 36 domain catalogs declare exactly 694 unique feature IDs. The global catalog and `handoff/features/` population must match those domain catalogs exactly; orphan, missing, duplicate, foreign, or wrong-domain packages are invalid.

The current manifest-derived distributions are:

- package: 693 `finalized`, 1 `pilot`;
- scientific: 60 `defined`, 137 `partially_defined`, 222 `external_provider_required`, 275 `preserved_unresolved`;
- execution: 25 `executable`, 237 `conditionally_executable`, 432 `structural_only`;
- examples: 1 present, 693 absent.

These status dimensions are independent. Structural finalization does not imply scientific executability, and `external_provider_required` does not authorize invention of provider semantics.

## Global catalog

`handoff/catalog.json` is the deterministic projection generated by `tools/handoff/generate_catalog.py`. It records the authoritative domain order, all 694 feature descriptors, package/scientific/execution statuses, examples presence, resolved shared dependencies, package and descriptor SHA-256 fingerprints, tool versions, and explicit deprecation/substitution fields.

No timestamp or volatile normative field is permitted. CI reconstructs the catalog from committed artifacts and requires exact equality.

## Validation authority

`tools/handoff/validate_handoff.py` is the sole normative handoff validation CLI. `tools/handoff/model.py` centralizes model identity, population, domain order, shared-contract, and tool-version constants without acting as a second validator.

The validation surface checks:

- exact 36-domain and 694-feature population;
- schemas and mandatory package files;
- domain ownership and ordered populations;
- cross-file feature identity;
- shared dependency closure;
- traceability completeness;
- unique test, operation, and error identities where required;
- strategy-order constraints;
- deterministic global catalog equality;
- absence of normative runtime implementation code.

The permanent workflow also runs logical self-tests and deterministic standalone export verification.

## Shared-contract model

Exactly eight shared contracts are published. A shared carrier establishes structural reuse only; it does not establish scientific identity or equivalence across domains.

Promotion of any additional shared contract requires demonstrated independent-domain equivalence, semantic neutrality, parameterizable local differences, net structural benefit, and source-backed conformance expectations.

## Standalone exports

`tools/handoff/export_bundle.py` resolves each catalog feature into exactly:

```text
feature/
shared/
bundle-lock.json
```

The lock records feature and model versions, transitive shared contracts, source and bundle paths, ordered SHA-256 file records, per-shared-package hashes, and an aggregate bundle hash. It contains no timestamp. Scientific sources, registry artifacts, and intermediate IRs are never copied.

The permanent workflow selects all 694 catalog features and generates each bundle twice in independent temporary directories. Lock objects and every relative-path hash map must be byte-for-byte identical. Bundle archives are not committed.

## Scientific boundary

No handoff artifact may invent an equation, proof, value, threshold, type, endpoint, transition, causal interpretation, evaluator, solver, convergence rule, provider behavior, or scientific alias absent from source authority.

The global scientific-review registry preserves 147 recorded review questions, and domain-level unresolved/provider boundaries remain explicit in their own registries and package traceability. Structural finalization does not approve or answer them.

## Protected authority

Scientific source texts under `maths/` remain upstream authority. Registry artifacts provide the auditable transformation path; handoff packages provide the final language-neutral programmer interface.

Historical reconciliation and domain-production reports remain audit evidence. They do not override the current 36-domain / 694-feature catalog population.

## Production result

Feature Handoff Package v1.0 is structurally finalized for the repository's full production corpus. It provides deterministic, traceable, implementation-neutral packages for all 694 feature identities while preserving every declared scientific limitation.

Runtime implementation remains outside `tllib-specs`.
